# StroySync — краткое описание решения (промежуточная сдача)

## Подход и технологии

StroySync связывает **снимок камеры** с **этапом календарного графика**, а не останавливается на детекции. Техника распознаётся open-vocabulary моделью **YOLO-World** (запасной путь — YOLOv8 COCO, для питча — детерминированный demo). Backend — **FastAPI**, интерфейс — **React**, данные — **PostgreSQL/SQLite**, поставка — **Docker Compose**.

Каждая камера привязана к зоне и списку WBS. Этап описан тройкой множеств техники: обязательно / допустимо / запрещено, плюс «отпечаток» typical_signature. Соответствие считается как Jaccard; предупреждение ссылается на конкретное правило и код этапа.

## Обнаружение техники

Классы ТЗ задаются текстовыми промптами: dump truck, excavator, road roller, knuckle boom crane, concrete mixer truck, bulldozer, cargo truck, mobile crane. На кадре рисуются боксы с русскими подписями. Модель открытая, без fine-tune на закрытом архиве; дообучение — план до финала, когда будет разметка площадки.

## Сопоставление с этапами

`дата снимка × linked_wbs камеры → активные этапы → сравнение состава машин`.

Примеры на 17.09.2026: CAM-01 / фундамент ожидает бетоносмеситель; каток в этом кадре — критическое FORBIDDEN_EQUIPMENT; пустой кадр — NO_ACTIVITY; состав «автокран + грузовик» на CAM-03 ближе к старту каркаса.

## Прогресс и план до финала

**Сделано:** прототип end-to-end (детект → матчинг → UI → API → БД), демо-сцены, график CSV/XLSX, Docker, тесты правил, черновик презентации и документации.

**До финала:** прогон на реальных снимках организаторов и открытых датасетах (разная освещённость/сезон), подключение YOLO-World в docker-профиле `ml`, при наличии разметки — короткое дообучение, 2–3 скриншота/короткое видео в презентацию, при необходимости — простой трекинг по серии кадров.
